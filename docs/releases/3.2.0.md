# de67 3.2.0 — GPT-6 update

This candidate moves new DE67 work to GPT-6 Sol, Luna, and Astra while preserving older session and clock records as evidence. It is based on the current Mac mini de67-lab machinery and the published 3.1.0 release history.

## Changes since 3.1.0

- Phase 2 probes the actual GPT-6 model and effort pairs needed by the target runtime. Existing workspaces with a GPT-5.6 roster need successful GPT-6 probes before new Phase-3 dispatch.
- Phase 3 uses Sol for coordination, Luna and Sol for ordinary work, and Astra for independent mutation review. Luna remains required for live harness playtests.
- Supervisor and worker handoffs carry the current owner contract and reject stale or mismatched prepared work. Existing durable history remains readable.
- The dashboard labels current Sol and Luna workers, preserves historical usage under other workers, and shows Astra review or owner-message activity.
- Jev Telescope and Jev Pit Crew ship as **separate experimental optional add-ons**. Both default to off. Telescope requires `rg` and explicit configuration before provider use; Pit Crew has no automatic provider transport.

## Packages and compatibility

The core, dashboard, Discord, Jev Telescope, and Jev Pit Crew are separate archives with matching version requirements. Jev manifests are marked `experimental`. The core works with all add-ons absent. Each archive records its source commit and file hashes; `SHA256SUMS` records archive hashes.

Use Python 3.10 or newer and the OpenAI Codex runtime described in the [installation guide](../install.md). Preserve the existing project specification, ledger, clock, worker records, and active service when upgrading. Do not replace an installed skill used by a live run. The add-on guides explain configuration, verification, and removal.

## Reproduce

From the reviewed, committed release source:

```text
python scripts/package_release.py --ref HEAD --version 3.2.0 --output /outside/checkout/release
```

The builder reads Git contents rather than uncommitted files. The screenshot in the README shows a synthetic campaign rendered by the dashboard; it is presentation evidence, not a live-run proof.
