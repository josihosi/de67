# Telescope in the playtest harness — inspection, 2026-09-18

Inspected the actual `Cataclysm-AOL-hostile-ecology-dev` harness. This is a bounded
integration recommendation, not authorization to change game evidence or an assertion
that the current Telescope already supports its record types.

## First useful insertion point: retained evidence queries

`tools/openclaw_harness/play_cli.py:179` implements `PlayerClient.evidence`.
It discovers bound native/NPC logs and retained cockpit responses, applies exact
run/actor/request/event filters, then calls `evidence_events.query`.

`tools/openclaw_harness/evidence_events.py:140` builds normalized events, preserves
source byte offsets/lengths/hashes, builds request/result links and retains an immutable
query snapshot. Today it returns the first page and continuation handles. When the
question is semantic rather than an exact field match, agents must choose filters,
read pages and correlate them themselves.

Add optional Telescope selection **over a bounded pool from that immutable snapshot,
after exact identity filters and before agent-facing paging**. Send candidate IDs and
compact, deterministically selected event fields. Keep the run/actor/request identity,
event time, native acceptance/failure and observation semantics visible in candidates.
Return original selected fields plus exact source handles; Jev writes no evidence.

Useful question: "The stalker stopped approaching: find events that distinguish lost
line of sight, an unfinished player activity, and a rejected movement request."
Select both supporting and contradicting records, then let the playtest worker decide
the explanation. Missing records remain missing evidence, never an inferred outcome.

This targets repeated broad `rg`, whole JSON records, manual JSON extraction, and
multiple irrelevant pages. It should run on diagnosis or ambiguous evidence questions,
not every move. Exact request-ID/event lookups should use the existing deterministic
query without a provider call.

## Second: indexed prior investigations and occurrence search

`tools/openclaw_harness/evidence_search_query.py:41` already implements
`EvidenceSearch.query`, with lexical retrieval and an optional local embedding route.
The code is present; this inspection did not establish which live indexes are populated.

Reuse its occurrence IDs, generation status, source handles and exact filters to build
a finite candidate pool. Jev selection/abstention belongs after that shortlist, before
returning/expanding raw source records. Do not replace `backend.embed` with a Jev call:
the existing backend expects vectors; Jev is a typed selector, not an embedding API.
There is no need for another index or a persistent model service.

Target question: "Was this same input-owner failure already investigated, and did the
earlier attempt prove a fix or only establish a transport problem?" Retain historical
bindings, dates, evidence status and source revision. Similar text is not equivalent proof.

## Third: closeout citation discovery

`tools/openclaw_harness/play_cli.py:354` exposes witness fields once the journal is
sealed. A bounded Telescope query can propose which journal entry IDs are relevant to
an assigned outcome, including contradictions. The worker still chooses the verdict
and exact checks; existing witness validation and evidence ceiling remain authoritative.

This may reduce reopening large journals and guessing citation paths. Do not force all
closeouts through Jev; small known journals need no semantic selection.

## Existing mechanisms to preserve

- `gameplay_display.py:30` already emits changed facts, removals, action changes and
  current native authority. `play_cli.py:339` uses it during response collection.
  Do not put a probabilistic selector between the player and required current controls,
  threats, native rejection, or decision-relevant changes.
- `evidence_display.py:116` already pages exact hash-bound JSON by selector. If an
  agent knows the hash/field, this is cheaper and more reliable than asking Jev.
- `cockpit_evidence.py:375` verifies a byte span with SHA-256 before decoding it.
  An appended log can keep an earlier span valid; replacing that span invalidates it.
  Preserve this finer identity instead of hashing the entire mutable log per question.
- Polling/build waits require local event/change waiting, not model selection.

## Concrete adapter gap

Current de67 Telescope candidates describe a file SHA-256 and line range (or a de67
checkpoint row). That is unsuitable for large one-line JSON records and append-only
playtest histories. Add a record candidate source containing:

`snapshot SHA / occurrence ID / original path / byte offset / length / SHA-256 /
JSON selector / run-actor-request bindings / original evidence status`.

Candidate text is an exact deterministic projection, not a summary generated by Jev.
Selected records must be recovered using the existing verified harness functions;
changed records are reported stale. Reuse existing Telescope typed choices, independent
counterevidence question, input/evidence budgets, cache, off/shadow/on and fallback.
Cache keys must include the immutable snapshot and projected content, query/hypothesis
and provider configuration. Keep external transmission explicitly opt-in.

## What was actually tried

One live Telescope source query searched four harness source/documentation files.
It considered 12 of 17 lexical candidates, disclosed truncation, and selected the
existing evidence/query/recovery surfaces, including counterevidence to the hypothesis
that every observation needs model summarization. No fallback. Provider usage:
**7,179 input + 1,371 output = 8,550 tokens**. No gameplay logs were sent externally.

This proves source-location assistance only. No token reduction on actual playtest
histories has been established. The query also demonstrates why invoking Jev for
routine known-file reads is unlikely to pay: its own input is material.

## Smallest meaningful comparison

Use a frozen retained run and three real questions: a native-action rejection,
misleading hypothesis with available counterevidence, and a genuinely absent event.
First ensure the bounded candidate pool contains independently labeled important
records. Compare existing `evidence`/selector paging against Telescope on that same
pool and evidence budget. Measure correct answer/citations, missed contradictions,
abstention, subsequent page reads, fresh agent tokens plus provider tokens, and total
elapsed time. A record-count reduction alone earns no efficiency claim.

Priority: evidence-query adapter first; indexed historical retrieval second; optional
closeout citation search third. The earlier token audit's 1,138 worker source/log reads
identify an opportunity, not a count of calls that Telescope can eliminate.
