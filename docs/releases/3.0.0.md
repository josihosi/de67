# de67 3.0.0

This release brings the current Mac-tested DE67 runtime into the public skill, building on
v2.0.0 while preserving the three explicit commands.

## Changes since 2.0.0

- Persistent named Luna/Terra workers use Codex App Server conversations. A fresh coordinator can
  resume useful returned work; a returned turn no longer has to pretend its task is complete.
- Direct owner messages can reach the native mutator or coordinator through the optional Discord
  relay. Persistent mutator context and durable input receipts survive normal continuation.
- Functional-specification resolution supports canonical `FS.md` with a hash-bound legacy `DFS.md`
  pointer. The dashboard follows the same resolver.
- Owner-wait routing distinguishes an unfinished outcome from currently executable work.
- Git checkpoints are coordinator-chosen snapshots. Startup, review, and continuation no longer
  require a successful commit/push transaction to proceed.
- Review cadence uses 20–50 terminal windows, preserving prior evidence and already-due reviews
  when migrating existing state. Deadline-generation compatibility retains recorded history.
- The dashboard includes persistent-worker activity, observed usage, and the mission radar.
- `de67 release` loads release guidance separately from the delivery phases. The README is now a
  short entrypoint with setup and reference links.

## Packages

| Archive | Contents |
| --- | --- |
| `de67-3.0.0-core.zip` | Router, phases, runtime scripts, tests, references, and documentation. No executable dashboard or Discord integration. |
| `de67-3.0.0-dashboard.zip` | Optional dashboard code, local refresh script, tests, and agent-facing setup. |
| `de67-3.0.0-discord.zip` | Optional direct-input, blocked-only, and advisory adapters with their distinct setup instructions and tests. |

Each archive uses the same `de67/` root. Add-ons require the matching core version and can be
installed by merging their directory into it. Package manifests record the exact source commit
and every file's SHA-256; `SHA256SUMS` records archive hashes. The core includes the add-on setup
documents so Codex can explain prerequisites before installing either integration.

## Compatibility and migration

This is a Codex-specific workflow. Persistent workers rely on the Codex App Server; it is not a
provider-neutral orchestration library. Python 3.10+ is required. The Unix App Server route needs
`websockets>=15,<16`; the bundled detached service requires macOS and `tmux`. Native Windows keeps
the CLI route and shared logic. See [installation](../install.md) for the supported routes.

Preserve project state during upgrades. Do not replace a running installation or delete its clock,
worker registry, mutator conversation, specification, or ledgers. Follow the
[external supervisor lifecycle](../../de-67-3/references/external-supervisor.md) when an actual
service transition is needed. Optional packages require explicit configuration and remain removable.

## Reproduce the package

From a clean checkout of the reviewed source commit:

```text
python scripts/package_release.py --ref HEAD --version 3.0.0 --output /outside/checkout/release
```

The builder uses committed Git contents, not the working tree, and omits runtime state and historical
lab reports. Run the tests in [installation](../install.md) and each selected integration's guide
against extracted archives before publishing. Browser checks exercise refresh and radar layout;
a screenshot is presentation evidence, not proof of a product's gameplay or completed work.
