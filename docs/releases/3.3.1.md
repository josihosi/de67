# de67 3.3.1 — Preserve the conversation and the work

Patch release after [3.3.0](3.3.0.md), with an illustrated [2:41 introduction](../assets/de67-explainer.mp4?raw=true).

## Changes

- Method updates resume the same coordinator conversation with refreshed contracts. Owner-authorized clarifications can amend a named unfinished slice while independent work continues; installing method changes still requires its separate review and activation boundary.
- Durable agent mail can wake an eligible idle conversation, deliver each original message once, and preserve uncertain delivery receipts. Direct Discord input defaults to the coordinator; `mutator:` or `m:` selects the reviewer. Distinct follow-up replies retain their order.
- Named Luna and GPT-6.1 Sol workers request Fast service on start, resume and new turns. This does not establish measured per-turn speed or native helper inheritance; Astra's route is unchanged.
- The optional dashboard combines coordinator and Sol-worker usage in one Sol series, alongside Astra and Luna. Other worker usage remains accounted for in the total.
- Concurrent deadline-schema reopening retains one immutable claim-closure trigger. Optional Pit Crew observation remains attached to durable worker events, including when the add-on is absent or unavailable.
- Read-only host footing reports exact repository and requested process identities on macOS/Windows. Luna playtest workers can consult a reusable Sol helper for diagnosis while retaining game input. Explicitly scoped method-candidate assignments use the existing task and packet route without inventing product specification slices.
- The README starts with the public explainer video and a new synthetic campaign rendered by this candidate's dashboard. Core and optional archives retain their separate installation boundaries and prior Windows fixes.

## Packages and compatibility

Use matching **3.3.1** archives: core, optional dashboard, optional Discord, experimental Jev Telescope, and experimental Jev Pit Crew. Both Jev routes default to off. Core runs without any executable optional integrations installed.

Python 3.10+, Git, and authenticated OpenAI Codex are required. Persistent named workers and live input use the macOS/Linux Unix App Server route with `websockets>=15,<16`; the bundled detached service is macOS-only and needs `tmux`. Windows supports shared logic and CLI transport, plus the portable host-footing probe. Telescope needs a working installed `rg` in its Python process's environment.

Upgrade from matching archives and verify the new installation before starting a fresh run. Preserve existing project specifications, ledgers, databases, worker histories and receipts; do not replace an installed skill used by an active run. See [installation and upgrade](../install.md) and [supervisor lifecycle](../../de-67-3/references/external-supervisor.md).

## Current limits

Host footing is a point observation, not launch admission or a capacity test. Automatic cross-host source synchronization, enforced concurrent-run isolation and host ownership in the dashboard are still staged work and are excluded from this release. The method-candidate route only prepares a bounded packet; its marker grants no installation or activation authority. The separate video-making skill remains outside the release.
