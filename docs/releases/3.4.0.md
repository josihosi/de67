# de67 3.4.0 — Terra release

This release adds GPT-6.1 Terra to the supported worker model and effort choices, and makes a safe model or effort handoff possible for a returned, still-owned assignment after pending requests settle. The same task, worker conversation, and ownership continue. Active or ambiguous requests and changed jobs remain protected.

The current owner direction favors Terra for clear, testable coding, with Sol for concrete ambiguity, substantial coupling, architecture, or demonstrated difficulty. Choose thinking effort independently; this is not a quota or an extra Sol review layer. Sol remains the coordinator, Astra the mutation reviewer, and project-specific live playtesting may assign native input to Luna. The packaged selection guidance admits Terra but does not yet enforce the newer Terra-first preference.

The optional dashboard shows Terra and its supported effort levels. It reads retained, deduplicated response accounting from the existing work-context index, including usage attributed to the producing model. Cumulative observed totals and the 24-hour graph are separate; older coverage is marked partial. Runner checkpoints retain already observed responses when logs rotate. The dashboard remains read-only and independent of core operation.

A named-worker wait can wake for pending coordinator mail without consuming it. Support-only work with a sealed nonproduct dispatch and completed receipt has a supported acceptance path without inventing a product closure gap. Guidance distinguishes reporting an observation from attributing a bug, and supports choosing a valid continuation, replay, or restart by the remaining work.

Upgrade the core and any installed add-ons together using the matching release archives. See [installation](../install.md), [dashboard setup](../../integrations/dashboard/README.md), and [OpenClaw/Discord setup](../../integrations/openclaw_discord/SETUP.md). Existing optional Jev packages remain experimental. No new credentials are required for the core. Historical session model identities remain unchanged.

These changes are based on focused review and tests; they do not establish performance gains, universal stability, or a real provider turn on every platform.
